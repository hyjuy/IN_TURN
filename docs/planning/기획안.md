# NCS 기반 AI 직무 성장 시뮬레이션 게임 기획안

> **문서 버전:** v1.0 (2026-11-14)
> **개발·검증 마감:** 2026-11-22
> **대상:** AI 에이전트 해커톤 / 4인 팀 가정
> **문서 상태:** 개발용 기획안 — 사실, 가설, 미확정 사항을 구분하여 작성

## 1. 한 줄 소개

**가상 회사에 신입사원으로 입사해 AI 상사·동료와 일하고, 선택의 결과로 성장하는 게임. 게임 속 행동을 NCS 수행준거에 연결해 자신의 직무 판단 방식과 보완할 역량을 돌아본다.**

- **재미의 중심:** 프린세스 메이커형 성장·자원 관리·인물 관계·분기 이야기.
- **AI의 역할:** 과거 사건을 기억하는 NPC, 사용자 행동에 따른 후속 사건, 근거 중심 피드백.
- **교육적 근거:** NCS 직무 능력단위·수행준거·직업공통능력 및 직업정보.
- **사업 방향:** 청년센터·대학 취업지원센터·직업훈련기관(B2G/B2B), 이후 기업 신입사원 교육.
- **중요한 한계:** 게임 결과는 실제 직무 역량, 채용 적합성, 심리 특성을 확정 판정하지 않는다.

## 2. 문제 정의와 사용자

### 2.1 해결할 문제 — 검증이 필요한 가설

취업 준비생이 직무명을 알고 있어도 실제 업무 흐름, 우선순위 판단, 동료와의 협업, 업무 압박 등을 경험하기 어렵고, 자신의 행동을 근거로 직무 적합성을 돌아볼 기회가 부족할 수 있다.

이 문제의 **존재 규모 및 기존 서비스의 미해결 정도는 아직 실증되지 않았다.** 취업 준비생 면담과 현직자 시나리오 검토로 확인한다.

### 2.2 대상 구분

| 구분 | 대상 | 기대 가치 |
|---|---|---|
| 이용자 | 취업 준비 청년, 직무탐색 학생 | 부담 없는 직무 경험, 자기이해, 학습 방향 |
| 잠재 구매자 | 지자체 청년센터, 대학 취업지원센터, 직업훈련기관 | 직무탐색 교육 프로그램, 참여·학습 기록 |
| 후속 구매자 | 기업 인사·교육부서 | 신입사원 업무·소통 교육 |

**구매 의사와 지불 의향은 확인되지 않았다.** 기관 운영자 면담 및 소규모 시범 운영으로 검증한다.

## 3. 차별화 전략

### 3.1 기존 서비스와의 비교

| 비교 대상 | 기존 특징 | 우리의 검증 목표 |
|---|---|---|
| JobSim | AI 다중 인물 직장 시뮬레이션 | 한국 NCS 근거, 청년 진로탐색, 육성형 성장 경험 |
| Attensi | 게임형 기업 교육·AI 역할극 | 취업 전 직무 이해와 개인별 행동 근거 기록 |
| Forage | 기업의 실제 직무 과제 체험 | 대화형 NPC, 선택의 장기적 결과, 관계 변화 |
| 코멘토 직무부트캠프 | 현직자 과제·피드백 | 짧고 반복 가능한 개인 체험, 낮은 진입 부담 |
| 범용 AI 챗봇 | 자유로운 직장 상황극 | 검증된 게임 상태, 일관된 결과, NCS 연결 평가 |

**차별점은 ‘AI NPC가 있다’가 아니라 ‘선택 → 기억 → 사건 변화 → 성장 → 수행 근거’의 폐회로를 실제로 구현하는 데 있다.** 경쟁 서비스에서 이와 비슷한 기능을 제공할 수 있으므로 우월성은 비교 실험으로 판단한다.

### 3.2 제품 원칙

1. **게임 우선:** 먼저 재미있어야 한다. 설명식 교육, 긴 문항, 연속적인 검사 화면을 피한다.
2. **선택의 대가:** 모든 선택에는 이득과 기회비용이 있고, 나중에 이야기로 되돌아온다.
3. **살아 있는 동료:** AI 인물은 설정된 성격·기억·관계를 유지하며 상황에 반응한다.
4. **평가의 정직성:** 게임 수치와 실제 역량에 대한 관찰 기록을 분리한다.
5. **사람의 통제:** 안전 규칙, 게임 상태 및 평가 준거는 LLM이 임의로 변경하지 못한다.

## 4. 게임 디자인

### 4.1 기본 콘셉트

- **가제:** 《첫 출근, 90일》 (해커톤 시제품은 **5일짜리 축약판**)
- **장르:** 2D 성장형 직장생활 시뮬레이션 + 대화형 사건 + 경량 자원 관리
- **초기 직무:** 생산기술 1개 (팀 내 직무·시나리오 검토 가능성을 기준으로 임시 선정)
- **플레이 시간:** 해커톤 시연용 한 회차 **약 10분 목표**
- **화면:** 회사 사무실·현장 일러스트, 인물 대화, 일정·자원·상태 패널, 결과 보고서

### 4.2 핵심 순환 구조

`하루 일정 선택 → 업무/관계 이벤트 → AI NPC와 대화 및 행동 → 상태·관계·기억 갱신 → 후속 사건 발생 → 성장·피드백`

- **육성 수치(가상의 게임 값):** 경험치, 직급, 업무 숙련, 체력, 시간, 스트레스, 동료 신뢰.
- **보상:** 새로운 대사·업무 해금, 별명·배지, 작은 승진 이벤트, 다른 결말.
- **관계:** 도움·약속·갈등·사과 등 사건이 이후 NPC 행동에 영향을 줌.
- **갈등:** 효율 vs 안전, 개인 성과 vs 협업, 마감 vs 품질처럼 상충하는 목표.
- **실패:** 즉시 게임오버보다 상황 악화, 관계 변화, 재도전·재계획으로 이어짐.

### 4.3 5일 MVP 이야기

| 일차 | 핵심 사건 | 재미 요소 | 관찰 요소(NCS 연결 후보) |
|---|---|---|---|
| Day 1 | 신입사원 첫 업무 지시 | 상사·선배 소개, 첫 인상 | 요구사항 확인·의사소통 |
| Day 2 | 생산 실적과 불량 증가 | 자료 탐색·제한 시간 | 수리·문제 원인 분석 |
| Day 3 | 동료와 업무 충돌 | 관계 선택, 과거 도움의 회수 | 협업·대인관계 |
| Day 4 | 납기 압박과 안전·품질 판단 | 자원 관리, 후속 사건 분기 | 우선순위·직업윤리 |
| Day 5 | 결과 보고와 평가 | 엔딩·배지·행동 기반 보고서 | 문서소통·근거 제시 |

**핵심 시연 장면:** Day 2에 선배를 도와주거나 거절한 결정이 Day 4의 자료 접근·동료 협력에 영향을 준다. 사용자는 자신의 선택이 기억됐음을 체감한다.

### 4.4 콘텐츠 범위 통제

**필수:** 직무 1개, 일차 5개, 주요 사건 3개 이상, AI NPC 2명, 상태·관계 변화, 최소 1개 기억 기반 후속 분기, 행동 근거 보고서.

**시간이 남으면:** 엔딩 2종, 배지 3개, 재플레이 동선 개선, 소리·간단한 애니메이션.

**이번 개발에서 제외:** 3D 오픈월드, 직무 수십 개, 음성 NPC, 실제 채용 합격률 예측, 공식 SKCT/GSAT 점수 산출, 인사평가·심리진단.

## 5. AI 에이전트 설계

| 역할 | 입력 | 출력 | 통제 방식 |
|---|---|---|---|
| 게임 진행 관리자 | 날짜, 상태, 사건 기록 | 다음 사건 후보와 진행 흐름 | 상태 전이·이벤트 조건은 규칙 기반 |
| 시나리오 에이전트 | NCS 준거, 사건 템플릿, 현재 게임 상황 | 상황 설명·후속 갈등 | 사건 범위, 안전 제약, 설정 검증 |
| NPC 에이전트 | 인물 성격, 관계, 기억, 현재 상황 | 상사·동료의 대화와 반응 | NPC별 사실·성격 일관성 검사 |
| 관찰·평가 에이전트 | 행동 로그, 과제 결과, NCS 수행준거 | 관찰 근거·보완점·불확실성 | 근거 없는 주장 차단, 준거 ID 표시 |
| 자기성찰 에이전트(선택) | 관찰 결과, 이용자 확인 | 선택 이유를 묻는 짧은 질문 | 성격 단정 금지, 이용자가 수정 가능 |

**구현 원칙:** 여러 LLM을 꼭 띄울 필요는 없다. 하나의 LLM과 상태기계, 도구 호출, 역할별 프롬프트로 에이전트 기능을 분리할 수 있다. 게임 상태 갱신은 검증된 함수가 담당한다.

### 5.1 상태 예시

```json
{
  "day": 3,
  "role": "production_engineer",
  "stats": {"xp": 120, "stamina": 60, "stress": 30},
  "relationships": {"senior": 15, "manager": 5},
  "flags": ["helped_senior_on_day2"],
  "task_status": {"quality_issue": "investigating"},
  "evidence": [
    {"event": "D2_QC", "action": "checked_defect_trend", "criterion_id": "NCS_TBD", "source_turn": 12}
  ]
}
```

`NCS_TBD`는 실제 능력단위·수행준거 확인 후 대체할 자리표시자다. 임의의 NCS 코드를 만들어 쓰지 않는다.

### 5.2 안정성 요구

- 사용자 입력이 길거나 예상 밖이어도 시나리오가 진행되어야 함.
- NPC 기억은 구조화된 사건 기록을 바탕으로 요약하며, 사용자에게 발생하지 않은 일을 꾸며내지 않음.
- LLM 출력은 JSON 스키마로 검증하고 실패 시 준비된 대사·규칙으로 대체.
- 평가 에이전트는 **관찰됨 / 근거 부족 / 관찰 기회 없음**을 구별.
- 안전·품질 관련 위험한 선택을 게임 내에서 긍정적 실무 행동으로 권장하지 않음.

## 7. 결과 화면: 재미와 평가를 분리

### A. 게임 결산 (허구의 세계관 수치)

- 레벨, 직급, 배지, 관계도, 주요 사건 회고, 분기별 엔딩.
- 수치는 게임의 재미·진행을 위한 것이며 실제 직무 역량을 의미하지 않는다.

### B. 직무탐색 보고서 (관찰 근거)

| 항목 | 표시 예시 |
|---|---|
| 관찰 행동 | 불량률 증가 시 최근 생산 기록을 먼저 확인함 |
| 관련 준거 | 확인된 NCS 수행준거 명칭·식별자와 근거 자료 |
| 잘한 점 후보 | 원인 가설을 제시하기 전에 자료를 확인하는 행동이 관찰됨 |
| 보완할 부분 | 관련 부서와 확인할 사항을 명확히 전달하는 과정은 관찰 부족 |
| 한계 | 이번 게임의 가상 업무에서 관찰한 내용으로 실제 능력을 확정하지 않음 |
| 다음 학습 | 관련 기초 학습자료·재도전 이벤트 연결 |

기록된 행동 근거를 사용자가 열람·수정 의견 제시할 수 있도록 하고, 기관용 화면에는 개인 대화 원문이 아닌 동의한 범위의 활동 현황만 전달한다.

## 8. 기술 구성(MVP)

- **프런트엔드:** 간단한 2D 웹 게임(React 또는 HTML/CSS/JavaScript 중 팀 숙련도에 따라 확정)
- **백엔드:** Python FastAPI
- **에이전트 흐름:** LangGraph 또는 명시적 Python 상태기계 + LLM API
- **저장소:** SQLite 우선(게임 상태·이벤트·행동 근거), 필요 시 PostgreSQL
- **직무 지식:** 검토된 NCS 준거 및 직업정보를 JSON/Markdown으로 로컬 관리
- **시연 안정성:** 준비된 초기 상태, 리셋 버튼, 이벤트 재현, LLM 실패 시 대체 분기

### MVP 완료 기준 (기능)

1. 시작부터 엔딩까지 중단 없이 1회 플레이할 수 있다.
2. 2명 이상의 AI NPC가 역할과 이전 사건에 맞춰 대답한다.
3. 최소 1개의 이전 선택이 다른 날짜의 사건·관계에 영향을 준다.
4. 선택에 따라 게임 수치가 일관된 규칙으로 갱신된다.
5. 최종 보고서가 **행동 로그 → 수행준거 → 판단 근거**를 연결한다.
6. 근거 없는 개인 성격·직무 능력 단정이 출력되지 않는다.
7. 시연 가능한 로컬/배포 실행 절차와 실패 시 대응 시나리오가 있다.

**권장 실험 조건:** 각 방식에 같은 문제와 시간 조건을 사용한다. 표본이 작으면 결과를 ‘예비 실험’으로 명시하고 통계적 효과가 입증된 것처럼 표현하지 않는다.

### 잠정 목표(실측 성과 아님)

- 시연 경로에서 게임 완주율 100%(팀 내부 테스트), 플레이 10분 내외.
- 핵심 분기 1개 이상 재현 성공.
- 평가 설명에 NCS 준거와 실제 행동 로그가 모두 존재.
- 실제 사용자/현직자 피드백 1회 이상 반영.

## 12. 사업 모델 및 확장

### 12.1 초기 판매 가설

- **B2G:** 지자체 청년센터의 진로탐색 프로그램 이용권.
- **B2B:** 대학 취업지원센터·직업훈련기관의 교육 과정 단위 라이선스.
- **후속 확장:** 기업 신입사원 직무 적응 훈련용 시뮬레이션.

구매자에게 제공하는 가치는 'AI 대화 사용권'이 아니라 **짧은 직무 간접경험, 참여 활동, 행동 근거 중심 피드백, 반복 활용 가능한 교육 콘텐츠**다.

### 12.2 사업화 전 확인할 사항

1. 청년센터·대학이 어떤 진로 프로그램을 유료로 도입하는가?
2. 콘텐츠당 제작·검증 비용이 어느 정도인가?
3. 현직자 검증 없이는 어떤 오류가 발생하는가?
4. 기관의 개인정보·보안 요구사항을 충족할 수 있는가?
5. 운영자가 게임 기록을 어떤 수준까지 필요로 하는가? (민감한 대화 원문 제공은 원칙적으로 배제)

## 15. 3분 발표 메시지

1. **문제:** 취업 전 실제 업무와 협업 상황을 경험할 기회가 제한적이다(추가 검증 필요).
2. **해결:** AI가 살아 있는 직장생활을 만들고, 게임 선택이 다음 사건과 캐릭터 성장에 연결된다.
3. **기술:** NPC·상태·시나리오·평가 에이전트 + NCS 수행준거 + 규칙 기반 게임 엔진.
4. **차별점:** 재미있는 성장형 게임을 끝내면 ‘점수’보다 ‘내가 왜 그렇게 행동했는지’가 남는다.
5. **실증:** 고정형 게임/일반 챗봇과 비교한 사용자 경험·평가 근거·작동 안정성 결과.
6. **활용:** 청년센터·교육기관 직무탐색 프로그램으로 시범 적용 후 구매 검증.
